Version 0.8.2  （全新简约图标）
发布日期：2026-10-18

【变更】
1. 换掉沿用自旧版本的老图标，重绘一套简约图标
   · 构图：蓝色圆角方块 + 顶部白色横杠 + 粗白向上箭头，一眼看懂「顶到最上面」；
   · 9 个尺寸：16 / 20 / 24 / 32 / 40 / 48 / 64 / 128 / 256，覆盖托盘、标题栏、
     任务栏、资源管理器大图标等全部场景；
   · 16~32 像素采用独立的“小尺寸版本”（横杠加粗、箭头放大），
     不是把大图硬缩小，因此托盘里依然清晰；
   · 256 / 128 用 PNG 帧压缩，其余用传统 DIB 帧，保证 System.Drawing.Icon
     与托盘图标 100% 兼容；整个图标 52 KB，比旧图标（99 KB）小一半。

2. 修复窗体资源被还原成旧格式导致的编译失败
   若 .resx 里出现 Color1 / Bitmap1 / Icon1 / $this.Icon 等二进制资源，
   新版 MSBuild 会报 MSB3822 / MSB3823。三个窗体的 resx 已重新清空，
   图标统一由 AppIcon.Get() 从嵌入的 icon.ico 读取。

Version 0.8.0  （置顶描边 + 快捷键彻底修好 + 免装 Developer Pack）
发布日期：2026-10-18

【新增】
1. 置顶描边
   置顶成功的窗口四周会显示一圈描边，一眼就能看出哪些窗口被钉住了。
   · 颜色可以在「设置 → 描边颜色」里用取色器任意指定，默认深灰黑 #1F1F1F；
   · 可以整体关闭（部分用户更喜欢只用快捷键、不要任何视觉变化）；
   · 描边是独立的一层窗口，鼠标点击/拖动/滚轮全部穿透到原窗口，
     不会出现「边框上点不动」的问题；
   · 会跟随窗口移动、缩放、贴边、最大化，窗口最小化时自动隐藏；
   · 使用 DWM 的可见边界定位，不会像 GetWindowRect 那样多出一圈透明边距而留缝。

【重要修复：快捷键完全没反应的真正原因】
2. 热键接收窗口从来没有创建成功
   HotkeyWindow 构造时新建了 CreateParams 却没有设置 ClassName，
   CreateWindowEx 因此直接失败，窗口句柄为 0。
   RegisterHotKey 拿到 0 便退化成「线程级」注册，WM_HOTKEY 被投递到
   一个没有窗口过程的线程队列里——程序认为注册成功，按键却毫无反应。
   这是 0.7.0 版最隐蔽的一个缺陷。现在指定了窗口类并加了失败日志。

3. 旧配置里的 Ctrl+Space 与中文输入法冲突
   旧版本默认快捷键是 Ctrl+Space，中文系统里这个组合几乎一定被输入法占用，
   注册必然失败。程序读到这个历史默认值时会自动迁移为新默认的 Ctrl+Alt+T。

4. 快捷键被占用时自动换一个
   以前只是弹个提示，用户不换就永远用不了。现在会按
   Ctrl+Alt+T → Ctrl+Shift+T → Ctrl+Alt+F12 → Ctrl+Shift+F12 的顺序
   自动挑一个可用的，写回设置并提示，保证快捷键一定能用。

5. 新增 diag.log
   %LOCALAPPDATA%\AlwaysOnTop\diag.log 会记录快捷键注册结果与窗口句柄，
   以后遇到快捷键问题不用再猜。

【构建方式变更：不需要再装 .NET Framework 4.8 Developer Pack】
6. 工程改为 SDK 风格，并引入微软官方引用程序集包
   Microsoft.NETFramework.ReferenceAssemblies。
   原来那种旧式 csproj 编译时必须能找到「引用程序集 / Targeting Pack」，
   只装 .NET Framework 4.8 运行时（Windows 11 自带的就是运行时）会报
   "The reference assemblies for .NETFramework,Version=v4.8 were not found"。
   现在只要有 .NET SDK，或用 Visual Studio 2022 / VS Code 直接打开即可编译，
   不用再单独下载 100MB 的 Developer Pack。

7. 清理了各窗体 .resx 里遗留的 Color1 / Bitmap1 / Icon1 图标资源
   这些资源代码里从未使用，却会让新版 MSBuild 的资源生成器报
   MSB3822 / MSB3823 错误。窗体图标改为从嵌入的 icon.ico 读取。

8. 默认不再改写窗口标题
   有了描边之后，[置顶] 标题标记默认关闭（仍可在设置里打开）。

Version 0.7.0  （Windows 11 适配版 / 全中文界面）
发布日期：2026-10-18

本次做了两件事：修掉旧版本影响可用性的缺陷，把界面与提示全部汉化。

【核心缺陷修复】
1. 置顶后无法取消（最严重）
   旧版本用「窗口标题」在全进程里查找目标窗口，并在标题尾部追加 " - AlwaysOnTop" 作为标记。
   浏览器、VS Code、终端这类会不停刷新标题的程序，标记一秒钟就没了，
   于是再也找不到那个窗口，只能重启程序或手动改标题。
   现在改为直接持有窗口句柄(HWND)，标题怎么变都能准确取消置顶。

2. 取窗口标题的死循环
   Methods.GetWindowTitle() 里写的是 while (i < 1) 但 i 从未自增，
   一旦前台窗口没有标题（桌面、某些 UWP 窗口），就会 100% 占满一个 CPU 核心并卡死程序。
   现在改为单次读取，失败返回空串。

3. “点击你想置顶的窗口”这个流程根本没实现
   代码里 ChangeCursors() 紧接着就是 RevertCursors()，
   十字光标刚设上就被还原，随后直接读当前前台窗口——而此刻前台通常是任务栏。
   现在用低级鼠标钩子实现了真正的拾取：左键点谁就操作谁，右键/Esc 取消。

4. 全局键盘钩子的问题
   - CapsLock 打开时组合键失效（键码里混进了 CapsLock 位，KeyCode 比对永远不等）；
   - Win+字母 组合永远匹配不上（Win 键不在 Keys.Modifiers 里）；
   - 构造时 hook() 调了两次，泄漏一个钩子句柄；
   - 系统级键盘钩子会给全系统的每次按键增加延迟。
   现在改用 RegisterHotKey + 隐藏消息窗口，由系统负责匹配。

5. 快捷键只剩一个修饰键时启动崩溃
   注册表里若存成 "Shift"，HK.Split('+') 后取 sHK[1] 直接索引越界，
   被外层 catch 捕获后弹一个异常框然后退出程序。

6. 64 位下的 P/Invoke 声明错误
   SetWindowPos 的 hWndInsertAfter 声明成 int（应为 IntPtr），且缺少 SetLastError；
   GetWindowText 没有指定 CharSet.Unicode，中文标题会读成乱码。
   已全部按 64 位 + Unicode 重写。

7. 其他
   - 托盘图标右键再左键会弹出两个菜单（Click 事件对左右键都触发）；
   - 左键菜单靠反射调用 NotifyIcon 私有方法 ShowContextMenu，脆弱且无异常保护；
   - 开机自启写入的路径没加引号，装在含空格的目录下会启动失败；
   - “自动检查更新”的周期设置永远写 0（勾了等于没勾）；
   - 更新检查用 WebClient 且没启用 TLS 1.2，Windows 11 上直接失败；
   - 更新流程会下载并直接执行远端 exe，改成只查版本号 + 打开网页；
   - 编译缺 System.Configuration 引用（Properties\Settings.Designer.cs 编译不过）；
   - 未做单实例，重复启动会挂两个托盘图标、两套热键；
   - 出错日志写在程序目录，装在 Program Files 下会因无权限再崩一次；
   - 退出时不还原已置顶的窗口，留下“永远悬在最上层”的窗口。

【Windows 11 适配】
* 新增 app.manifest：声明 DPI 感知（解决 125%/150% 缩放下界面发虚）、Win10/11 兼容性、asInvoker 权限。
* 托盘气泡（BalloonTip）在 Win11 对未打包应用经常不显示，改为自绘的轻提示卡片（右下角、不抢焦点、3 秒自动消失）。
* 托盘菜单从过时的 ContextMenu 升级为 ContextMenuStrip，外观贴合 Win11。
* 目标框架从 .NET Framework 4.5.2（已 EOL，新版 VS 不带该目标包）升级到 4.8。
* 新增「以管理员身份重启」菜单项：普通权限无法操作管理员窗口（UIPI 限制），
  置顶失败时给出明确提示而不是静默无反应。
* 界面字体统一为 Microsoft YaHei UI 9pt，按 DPI 缩放，中文字号与行距正常。

【界面汉化】
* 托盘菜单、设置、帮助、关于、更新提示、异常提示全部中文。
* 设置项精简为：开机自启 / 全局快捷键（可选 + 自定义）/ 标题栏置顶标记 /
  静默模式 / 启动时检查新版本。
  旧版本的「使用 Windows 系统菜单」「按标题永久置顶」「检查更新周期」
  三项长期挂着 "Coming soon!" 且控件被禁用，属于未实现的死功能，已移除。
* 快捷键录入改为直接按键捕获（ProcessCmdKey），支持 Tab/Enter/方向键，
  录入时先试注册一次，冲突会立刻提示「已被其他程序占用」。
* 设置改完立即生效，不再强制重启程序。

【工程清理】
* 删除未使用的 AlwaysOnTop 空窗体、FormUpdate 更新窗体、globalKeyboardHook、
  Octokit 依赖与 packages.config。
* 新增：Native.cs（P/Invoke 集中）、TrayContext.cs（主逻辑）、MousePicker.cs（十字准星拾取）、
  HotkeyWindow.cs（热键消息窗口）、ToastForm.cs（轻提示）。
