窗口置顶（AlwaysOnTop）  版本 0.8.2
==================================================

把任意窗口钉在最上层，便于边看资料边操作、小窗播放、监控面板常驻等场景。

一、怎么用
--------------------------------------------------
1. 程序启动后没有主窗口，只在任务栏右下角的通知区域显示一个图标
   （Windows 11 默认会收进「^」溢出区，建议拖到常驻区）。

2. 全局快捷键（最快）
   默认 Ctrl+Alt+T：直接把「当前活动窗口」置顶 / 取消置顶，一次按键来回切换。
   快捷键可在「设置」里改，改完立即生效，不用重启程序。
   如果这个组合被别的程序或输入法占用，程序会自动换一个可用的并提示你。

3. 十字准星点选
   左键单击托盘图标 → 「选择窗口置顶 / 取消置顶…」
   鼠标会变成十字准星，点击目标窗口即可置顶；
   再次对同一窗口操作即可取消。按 Esc 或点右键可中途取消。

4. 置顶的视觉提示：描边
   置顶成功的窗口四周会显示一圈描边（默认深灰黑），窗口移出置顶后立即消失。
   · 颜色：「设置 → 描边颜色」，点色块用取色器任意挑；
   · 不想要：「设置 → 置顶后给窗口加描边」取消勾选；
   · 描边不挡鼠标，点在边框上仍然是操作底下的窗口。

5. 另外可以在设置里打开「在窗口标题栏显示 [置顶] 标记」（默认关闭，会改写窗口标题）。

二、系统要求
--------------------------------------------------
Windows 7 / 8 / 8.1 / 10 / 11，32 位与 64 位均可。
运行时需要 .NET Framework 4.8（Windows 10 1903 之后与 Windows 11 已内置）。
注意：只需要「运行时」，不需要装 Developer Pack。

三、常见问题
--------------------------------------------------
Q：按了快捷键没反应？
A：先看 %LOCALAPPDATA%\AlwaysOnTop\diag.log 里的注册记录。
   如果显示「快捷键注册失败」，说明该组合被占用——本版会自动换一个可用的，
   也可以到「设置」里录入自己的组合。若日志里完全没有记录，请确认程序确实在运行
   （托盘有图标），并用「以管理员身份重启」试一次。

Q：某些窗口点了没反应，或者提示「无法修改置顶状态」？
A：那是管理员权限运行的窗口（如任务管理器、以管理员启动的终端）。
   普通权限的进程无法改变高权限窗口的 Z 序，这是 Windows 的 UIPI 限制。
   解决办法：托盘菜单 →「以管理员身份重启」。

Q：托盘气泡提示怎么不弹了？
A：Windows 11 对未打包应用的气泡提示支持不稳定，本版改为自绘的轻提示卡片，
   显示在屏幕右下角，3 秒后自动消失。不想看可在设置里关闭。

Q：卸载 / 退出后窗口还停在最上层？
A：正常退出会把本程序置顶过的窗口全部还原，描边也会一并撤掉。
   若程序被强制结束，窗口可能残留置顶状态，重新打开本程序再切换一次即可。

Q：配置存在哪里？
A：HKEY_CURRENT_USER\SOFTWARE\AlwaysOnTop
   开机自启写在 HKEY_CURRENT_USER\SOFTWARE\Microsoft\Windows\CurrentVersion\Run

四、编译
--------------------------------------------------
本版工程已改为 SDK 风格，不再依赖 Visual Studio 专用的引用程序集。

方式一：命令行
    dotnet build AlwaysOnTop.csproj -c Release
   产物在 bin\Release\AlwaysOnTop.exe

方式二：Visual Studio 2022
    直接打开 AlwaysOnTop.csproj，F5 即可（不需要装 .NET Framework 4.8 Developer Pack，
    工程里已通过 Microsoft.NETFramework.ReferenceAssemblies 包提供引用程序集）。

方式三：VS Code
    需要 .NET SDK（dotnet --version 能输出即可）与 C# 扩展。
    打开文件夹后按 F5（已附带 .vscode\launch.json 与 tasks.json），
    或直接在终端执行 dotnet build。

常见报错：「The reference assemblies for .NETFramework,Version=v4.8 were not found」
    这是旧式工程要求 Developer Pack 导致的。本版已通过 NuGet 包解决；
    如果仍出现，执行一次 dotnet restore 让包下载完整，或确认网络能访问 nuget.org。
